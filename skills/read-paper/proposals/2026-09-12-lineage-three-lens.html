read-paper v1.7 提案:脉络与三镜

日期 2026-09-12 状态 已采纳并实施(2026-09-12)。用户裁定:① connect 解禁 → 连但标出处;② 允许联网拉引用;③ 三镜等新三行全自动,不留右栏(否决了"右栏你填"的设计)。实施:note_schema_v2 §9、SKILL v1.7、模板、lesson_schema 第 6 条、AGENTS.md、scripts/lineage.py 动因 你 09-12 的话:"我拥有锤子,但并不是有钉子才有的锤子……我读论文不能仅仅为了学习知识,我还要知道他背后的脉络"

0你的话,翻译成 skill 的缺口

你说的是三件事,不是一件:

  1. 脉络:这篇从哪条线上长出来,它之前的人卡在哪,作者为什么在这个时候写它,它之后长出了什么。
  2. 为什么是它:它修了行业里什么"严重弊病",凭什么称得上 best paper 级。
  3. 用哪种人的脑子解的:robotics 的"在这个环境里能不能做成"、AI 的"难点到底在哪"、ML 的"方法为什么成立"。

对照 v1.6 的一屏卡(脊椎 / 四格 / 边界 / 裁决)和讲义(第 0 课讲"这篇解决什么"),这三件事一件都没有固定位置。更糟的是,v1.3 有一条明文规则:agent 不主动做跨论文 connect,理由是那是用户的认知工作。这条规则和你现在要的直接冲突。它当初防的是"agent 替你编关联",防法是不让 agent 连;正确的防法应该是连,但每条连线标出处。

诊断一句话:v1.6 教你把一篇论文吃透,不教你把它放回来处。读十篇是十个孤岛,广度有了,脉络没有。你形容的"有锤子没钉子"在读论文上的形态就是这个:每篇都懂,但说不出它们之间的缝在哪。

1借来的五个框架(网上查的,都是老东西,正好用)

框架它问什么拿来做什么
Heilmeier 八问(DARPA)①要做什么,不许用行话 ②现在怎么做、极限在哪 ③新在哪、为什么能成 ④谁在乎 ⑤风险 ⑥⑦成本时间 ⑧怎么验收②③④ 就是你要的"弊病 / 解法 / 为什么重要"。脉络格的骨架直接用它。
Marr 三层(计算 / 算法 / 实现)计算层:问题是什么、为什么这么定义;算法层:用什么表示和过程;实现层:在什么物理基底上跑和你的三镜几乎一一对应:AI 镜 ≈ 计算层(难点在哪),ML 镜 ≈ 算法层(方法为什么成立),robotics 镜 ≈ 实现层(在具体系统上能不能成)。这说明你的三镜不是随手分的,是有理论根的。
Keshav 三遍读法第一遍 5 分钟定"贡献类型";第二遍抓论证;第三遍复现第一遍就该答"这篇是哪一镜下的贡献"。v1.6 把三遍都做成了产物,但没有"贡献类型"这个字段。
Hamming《你和你的研究》大科学家花时间想"什么问题重要",而且开着门钉子不是从自己的锤子里长出来的,是从别人卡住的问题里长出来的。脉络格里"当时的极限"那一栏,就是在替你开门。
CoRL / ICRA 评审与奖项标准significance、novelty、claims 是否被实验建立、impact;奖项看 technical merit、originality、relevance、potential impact、clarity"为什么是 best paper"有官方答案:四项都高。脉络格里"新在哪"必须能对上 novelty,"谁在乎"对上 impact。

还有一个工具:Semantic Scholar 的 API 有 /paper/{id}/references 和 /citations 两个端点,能拉上游和下游。脉络格里的"上游 / 下游"可以半自动生成,再由 agent 从论文自己的 related work 里核对。

2三镜:把你的描述变成可操作的问题

镜这种人问的问题(你的原话)读一篇论文时的具体三问输出格式
Robotics在特定环境下能不能实现某个东西,pick and place 能不能又快又准① 什么系统、什么任务、什么环境(仿真 / 真机,n 多少)② 做成了没有,快不快准不准稳不稳(数字)③ 换个物体 / 换个场景还成不成一句"能不能"的判决 + 三个数字
AI任何一个问题难在哪里,像千禧年难题难在哪,然后用方法解决它① 这个任务的本质难点是什么(不是工程难:组合爆炸?分布偏移?不可观测?有损抽象?)② 现有方法为什么恰好在这里失败 / 不泛化 ③ 这篇把难点定位到了哪一步,有没有把它变成一个可测的量难点一句话 + "变成了什么量"
ML方法本身如何成立,为什么 flow matching 比 AR 好① 方法为什么成立,机制是什么(不是"它 work",是"它为什么 work")② 有没有证明 / 消融把机制隔离出来 ③ 和替代方法的差别落在哪条假设上机制一句话 + 证据强度(证明 / 消融 / 只有直觉)

三镜各填完,再加两格判决:

  • 这篇主要在哪一镜下成立:一篇论文通常只在一镜下是硬的,另外两镜是软的或空的。写清楚。
  • 哪一镜是空的:空的那格就是钉子候选。Jiayuan 问你"为什么 diffusion 比 AR 强"、你答了口号、她说没人知道——那就是 Zhu 那篇 ML 镜下的空格。
为什么三镜比"批判要点"有用
v1.6 的"边界 / 批判"是在问"它哪里不够硬",答案总是一堆条目。三镜是在问"它在哪一层硬、哪一层空",答案是一个位置。位置能累积成地图,条目不能。

3脉络:五格,每格要出处

格问什么出处要求
来处它接的是哪条线;上游 3 到 5 篇是谁;作者谱系(哪个组、师承、前作)论文自己的 related work + intro 里"building on our prior work"这类句子;可选 Semantic Scholar references
当时的极限这篇写之前,这件事怎么做,做到哪就卡住(Heilmeier ②)intro 第一二段几乎总有;标原句
弊病它要修的那个"严重弊病"一句话;是行业弊病还是学术弊病agent 的判断,但要指向上一格的原句
动作与代价新在哪(Heilmeier ③);为什么这时候能成(什么前置条件刚刚成熟);付出了什么代价(假设、范围)贡献列表 + 前作引用;代价从 limitations 与实验设置里抠
去处它之后长出了什么;谁在乎(Heilmeier ④);对我这条线意味着什么Semantic Scholar citations top-N(可选);"对我"那一句是 agent 的,标明
和 v1.3 的冲突,建议这样解:保留"不连到用户在职公司的论文"这一条(那是利益问题,不是认知问题);删掉"不主动 connect"。新规则:连,每条连线标出处;出处是论文原句、引用数据、或"agent 判断"三选一,不许混。

4v1.7 改动清单

4.1 一屏卡:从四行变七行

脊椎 + 脉络(来处 / 极限 / 弊病 / 动作与代价 / 去处,每条带出处) + 三镜(Robotics / AI / ML 各一句 + 主要在哪一镜成立 + 哪一镜空) 四格地图(本线四格) 边界 一句话裁决 + 钉子候选(空的那一镜里,只有谁能填的那个问题;标明"候选") 右栏三个新行同样留给你自己写;收尾定义不变(原四行填满即收尾;新三行不计入,免得门槛变高)。

4.2 讲义:固定加一课"脉络课",放第 0 课之前

内容顺序固定:时代背景 → 当时怎么做、卡在哪 → 这篇的动作 → 代价 → 它之后长出了什么 → 为什么评审会给它高分(steelman)。配一张谱系小图(上游三五篇 → 本篇 → 下游),SVG 内联。篇幅上限:讲义总量的 20%。

4.3 夯实:加三道题

  • 脉络题两道:"这篇之前的做法是什么、坏在哪?""这篇付出的代价是什么?"
  • 三镜题一道:"这篇主要在哪一镜下成立?哪一镜是空的?"

4.4 SKILL.md 与 schema 的改动

- v1.3:paper-card 移除 Connect;跨 paper connect 是用户的认知工作,agent 不主动做 + v1.7:一屏卡加脉络行;agent 主动连,每条连线标出处(原句 / 引用数据 / agent 判断三选一) + 仍然不连到用户在职公司的论文 + Step 3.5(可选,网络可用时):拉论文的 related work 段 + Semantic Scholar references/citations 前 10,存 lineage.json,供脉络课引用 + note_schema_v2 §2 一屏卡表加三行;§5 讲义表加"第 -1 课·脉络课"为必有 + lesson_schema 铁律加第 6 条:第 -1 课不许用本篇的术语描述"当时的极限",要用当时的语言

4.5 不改的

脉络格内容出处
来处三条线汇合:① 从算法专家做 teacher-student BC(自动驾驶 Zhang 2021、足式 Miki 2022、灵巧手 Chen 2023);② 穿越接触的规划(Pang 2023 全局接触规划、Suh 2025 CTR 信赖域与 PRM,均为 Pang 一系);③ 数据质量理论(Belkhale 2024:好数据 = 覆盖足够 + 熵低)。作者:Pang(Boston Dynamics AI Institute)+ Righetti(NYU)论文 intro 第 3–5 段与 Sec 2.1 原文引用

6样例二:Jin & Posa 2211.16657(已按 v1.7 试点写进它的 note.html)

脉络格内容出处
来处两条线:① 学混合动力学(ContactNets Pfrommer 2020;作者自己的 LCS 学习 Jin 2022);② 接触系统的实时 MPC(Aydinoglu 的 LCS-MPC、Posa 2014 的 direct method、Le Cleac'h 2021)。Posa 是 MIT Tedrake 出身(RSS 2014 direct trajectory optimization through contact);Jin 是 Posa 的博后intro 第 3 段 + Sec 2 + 作者简介
当时的极限全阶接触模型的 MPC 组合复杂度 $2^{TI}$;神经网络学不好刚性和多模态;足式里的降阶模型是手设计的,会漏关键动力学intro 第 2 段、Sec 2.4 原句
弊病学术弊病:大家要么全建模(算不动),要么全平滑(丢结构)。没人问"完成任务到底需要几个模式"intro 那句斜体问题;判断为 agent
动作与代价新在哪:把"降阶"定义为最小化 g-MPC 与 f-MPC 的任务性能差距,证明这个差距被"模型在 MPC 自己产生的数据上的预测误差"上界住,于是只用 on-policy 数据迭代学一个几个模式的 LCS。为什么这时候能成:LCS 学习(2022)和 LCS 实时 MPC(2022)刚成熟。代价:PWA 是线性化,大旋转不行;模式与物理接触没有一一对应;$\dim\lambda$ 靠试;只在仿真贡献列表、Lemma 1、Sec 7.4 discussion
去处对你:它给的"少数任务相关模式"是让规划器能从任意状态实时回答的性质;而且它的学习本身就是 on-policy 的——模型只需要在控制器自己走到的数据上准。这两点正对着 Zhu 那篇"DAgger 用不了"的缺口agent 判断,标明
镜这篇硬 / 软 / 空
Robotics仿真三指手转方块 / 移方块,4 分钟、4k 样本,>50 Hz / >30 Hz,终端误差 0.06 rad / 7.6 mm;无真机软(全仿真,MuJoCo)
AI难点定位到"模式数量的组合爆炸",并给出可测的量:任务性能差距 $\mathcal L(g)$ 与其上界(on-policy 预测误差)硬
ML为什么能成立:Lemma 1(Lipschitz 代价下,性能差距 ≤ 两个数据集上的模型误差),Lemma 2(g-MPC 数据是 f-MPC 的 $\epsilon$-驻点);算法只取零阶项,承认没做一阶检查硬(有证明,证明和算法之间有一步承认的松动)

7这怎么帮你找钉子

你的诊断是"广度和项目经验好,深度和总结脉络差"。这套改动对应的机制:

  • 脉络课强迫每篇答"它修了什么弊病"。做二十篇之后你手里就有一个弊病库,弊病库就是钉子的原材料。Hamming 说的"知道什么问题重要",就是这个库。
  • 三镜强迫每篇标出空格。空格累积起来会重复出现,重复出现的空格就是这个领域真正没解的问题。Jiayuan 那句"为什么 diffusion 比 AR 强没人知道"就是一个在很多篇里都空着的格。
  • "钉子候选"一行强迫你写"只有谁能填"。能填的人是你,它就是你的钉子;不是你,就放下。
