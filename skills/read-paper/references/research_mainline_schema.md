# 研究主线文件与三盏灯分类法（v1.9，2026-09-18）

> 起因：用户在读 Belkhale 2306.02437 时把一个批评升级成了研究命题，并要求「maintain 一个文件，这个文件是我们的 research 主线……每次我要求你调用 subagent 搜的时候，你都需要记录进去，这将是我们的钉子所在」，同时要求分类准则**必须包含「它一次性点亮了三盏灯中的哪几盏」**。
>
> 本文件规定：主线文件长什么样、三盏灯怎么判、以及每次检索必须往里写什么。
>
> 当前实例：`research-mainline.html`（工作区根目录）。

---

## 1. 什么时候建这个文件

当用户开始把「读论文」转成「找自己的问题」时就建，具体信号：

- 用户对一篇论文提出了一个**结构性批评**（不是没看懂，是觉得它不该那么做）；
- 用户开始问「有没有人做过」而不是「这篇讲了什么」；
- 用户要求派子代理做文献检索。

**一个工作区只有一个主线文件。** 它不是某条线的笔记，是**当前在追的那些钉子**。

**钉子可以有多颗（2026-09-18 Zesen 改定）。** 原话：「**我的研究主线中的钉子数量不唯一哈，你可以有多个不同的 idea，那个只是记录**」。所以：

- 第一部分开头放一张 **两三行的钉子对照表**（编号 / 一句话 / 状态），再往下每颗一块。
- 每颗独立走 §3 的四层判据（门槛 → 第一要素三问 → 分档 → 兜底），**独立记版本历史**。
- **不要为了「聚焦」去合并或砍掉一颗。** 用户明说这个文件是记录，不是决策。**agent 的职责是把每颗量准，不是替他选。**
- 同一颗钉子的旧表述仍然降级成版本历史，写明为什么被改。
- 一颗钉子被检索打死了，**不删，改状态为「已撤」并写明是被哪条证据打死的**——被否过的方向最容易绕回去。

---

## 2. 固定结构：**两部分，密度完全不同**

> 2026-09-18 用户改定：「我希望分两部分理解，第一部分是准确简洁的，即前面的结论部分。另一个是后面的台账部分，要多复杂有多复杂，重要的是覆盖全，因为我不会看那个，那个是给你看的」。

### 第一部分 · 结论（给用户，一屏读完）

**硬约束：一屏。** 桌面宽度下高度不超过约 1200 px。只放五样东西，多一样都要砍：

1. **钉子一句话**（大字框）
2. **三盏灯各靠什么亮**（三行表，每行一句）
3. **现在做哪三件事**（编号，每条一行）
4. **必须记住的约束**（通常 2–4 条，每条一个小框：最强的反面证据、实验设计的地雷、代价）
5. **版本表**（表述 / 为什么被改，各一句）

外加末尾一句「审自己提案」的测试。

**写法**：这一半是写给人读的，不是写给检索的。**不放出处链接、不放引用数、不放「待核」**——那些全归第二部分。用户读完应该知道「现在该干什么」和「不能说什么」，仅此而已。

### 第二部分 · 台账（给 agent，越全越好）

不追求可读性，**追求覆盖全**。用一条明显的分隔线和一句「以下是台账，给 agent 看的，你不用读」隔开。包含：

| 节 | 内容 | 为什么必须有 |
|---|---|---|
| §2 分类准则全文 | 三盏灯判据、一次性、关系标签、证据强度、记录纪律 | 准则写死才比得了 |
| §3 证据台账 | 可筛选的表，每篇一行，带出处、引用数、存疑标记 | 这是资产，会一直长 |
| §4 检索日志 | 每次检索一条：日期 / 起因 / 本地核查 / 派几个代理 / 结论 / **返回空的查询词** | 「查过没有」和「找到了」一样值钱 |
| §5 空位推导 | 分块列，标明哪块已被人做掉 | 钉子会被别人蚕食，要看得见 |
| §6 维护约定 | 「每次派代理检索必须追加 §4、追加 §3、重算 §5、必要时给钉子加版本」 | — |

**第一部分的每一条，都必须是从第二部分推出来的。** 两边不一致时以第二部分为准，并同步改第一部分。

**钉子的版本历史表两边都放**：第一部分放精简版（表述 + 为什么被改），第二部分不用重复。**不记录为什么改，下次会绕回被否过的老路。**

## 3. 分档判据（2026-09-18 Zesen 改定，取代「数灯」）

> **原三盏灯法作废为主序，降级成本节的输入。** 用户原话：「**robotics 的比重无关轻重，重要的是后面几个**」「**真相本身比他的应用要好**」「我本人更倾向于 science 风格，即发现道理，其次才是效果」。
>
> **触发这次修订的事实**：按旧的数灯法，2410（两盏）排在 Belkhale（一盏）之上，而用户的判断是「这一篇完全比不上前面那一篇」。**尺子错了，不是判断错了。**

### 3.0 四层结构，顺序不能换

1. **门槛**：动机与实验有没有 **mismatch**。它声称解决的和它实际测的不是同一件事 → 后面全部作废。
2. **第一要素**：无 mismatch 的前提下，**问题本身是否关键**。分档只在**问题同等重要**时才用来分高下。
3. **分档**（下表）。
4. **兜底**：AI 与 ML **都**不达标时，**开源数据集上的效果 > 私有数据集 / 真机上的效果**。真机 workload **较大降级**。

### 3.1 档位表

| 档 | 条件 | 为什么排这个位置 |
|---|---|---|
| **T1** | 极其清晰地指出某种东西可以被定量研究（AI 侧），**同时**用公式推导详细解释了为什么（ML 侧），**并且 testbed 是机器人** | 三件事由同一个贡献撑起。唯一「道理」与「能用」同时到位的档 |
| **T1−** | AI + ML 都占，**但 testbed 不是机器人**（纯理论 / 仿真 / 别的领域） | 只差一个 testbed。**钉子最好的原料**——见 §8.2「最便宜的三灯选题是把现成定理搬上真机」 |
| **T2·ML** | 只占 ML：给了机制 / 证明 / 能隔离因果的消融 | 用户裁定 **ML 占优于 AI 占**：「ML 侧是否能很好解释**要好于**单纯提出一个 AI 指标并 scale up」 |
| **T2·AI** | 只占 AI：把说不清的东西变成一个**推导 / 定义得出**的量，但不解释为什么 | 有尺子没道理。偏应用 |
| **T3** | **只占一部分**：那个量是**拟合或实测**出来的；用实验说明现象存在，没有严格证明 | 用户原话「**单纯用实验证明而非 ML 严格证明苍白无力**」 |
| **T4** | 靠**机器人实验的工作量** | 「对 workload 奖励」，但**是最低的一档** |

### 3.2 最要紧的新区分：A 灯不是二值的，看「那个量怎么来的」

| 取值 | 含义 | 例 | 后果 |
|---|---|---|---|
| **推出来的** | 从定义或机制**导出**，拿到数据之前就知道它该长什么样 | Belkhale 式 (6)、CUPID 的影响函数、DART 的「匹配到学习器误差」 | AI 侧算**占** → T2 起步 |
| **拟出来的** | 先跑实验，再对数据**拟**一个数 | 2410 的幂律指数、Zhu 的三个熵、DeepCore 的基准分 | 只算**占一部分** → **T3** |

这条把 §8.3 那个「量是机制的推论，还是事后被解释的测量」的测试，从二选一变成台账里的一栏（字段 `q`，取值 `def` / `fit` / `na`）。

### 3.3 台账要记的新字段

| 字段 | 取值 | 说明 |
|---|---|---|
| `tier` | T1 / T1m / T2M / T2A / T3 / T4 | 主序。渲染时按此排序，灯数不再是主序 |
| `q` | def / fit / na | 那个量是推出来的还是拟出来的 |
| `bench` | open / priv / sim / na | 兜底排序用：开源数据集 > 仿真 > 私有真机 |
| `tn` | 字符串 | 档位判定的理由，**可争的必须写明并点名请用户裁** |

### 3.4 这把尺子顺手解释了 §8 的校准结果

代理测出「RSS 2021–2025 的 17 位获奖者：真机 15/17、机制 3/17、A 灯 ≈ 0/17」，当时结论是「三盏灯不换奖」。**现在看得更清楚：奖项追踪的恰好是用户判为「无关轻重」的那一盏。** 这不是尺子失败，是**两套价值函数本来就不同**，而用户已明确选了哪一套。推论：按这套标准选的题大概率不得奖，但会是一个说得清的博士课题——**这是自洽的选择，不是遗憾。**

### 3.5 对 note.html 详略的约束

档位直接决定 note 怎么写，见 SKILL.md 硬规矩 17 与 18：**T2·AI** → 把那个量讲穿（是什么 / 能指代什么 / 怎么来的 / 怎么用），偏应用；**T2·ML 与 T1** → 四问照写并**更偏推导**；**T3 / T4** → 顶部速读块，讲义照常写完但不加厚。

## 3B. 三盏灯（原判据，现为分档的输入）

来源是用户 2026-09-07 会上记下的三个社区各自在乎什么。这里把它变成**可判定**的判据。

**只看这篇论文的核心贡献，不看它顺带说的话。**

| 灯 | 亮的条件 | 不算亮 |
|---|---|---|
| **R 机器人** | 有**具体系统上的证据**，且这个问题**有人正在为它付真实代价**。真机，或某个组当下被卡住的任务 | 只有仿真玩具任务；只有 benchmark 分数而没人因此改做法 |
| **A 人工智能** | 把一个**说不清的难点变成了能算的量**。拿到数据或 rollout 就能算出一个数 | 给问题起了名字；提了框架但没有可计算的实例 |
| **M 机器学习** | 给出**机制**：一个证明，或一组能隔离出因果的消融 | 相关性；上界变松但没证明真值变大 |

### 3B.1 「一次性点亮」是单独一栏，而且最要紧

三盏灯由**同一个贡献**点亮，和三个互不相干的章节各点一盏，是完全不同的事。后者是拼装，前者才是钉子。

**判据**：把其中一盏灯对应的那部分删掉，另外两盏会不会跟着灭？会 → 同一贡献；不会 → 拼装。

取值：`同一贡献` / `拼装` / `不适用`（只亮一盏）。

### 3B.2 打灯的纪律

- 打灯是 **agent 判断**，必须在备注里写清依据，**用户可随时推翻**。
- 争议要留在文件里。例：Belkhale 的 M 灯判暗，但备注注明「Data Noising 那组标定隔离是全篇最硬的一块，有人会认为它半亮，这一条可争」。**不要为了表格好看而消除争议。**
- 不要设「半亮」。二值加备注比三值好用，因为「几盏」要能直接数。

## 4. 对钉子的关系（第二个标签）

| 标签 | 含义 |
|---|---|
| **填了** | 它真的做了我们要做的事。**出现一条，钉子就得重写** |
| **填了一半** | 做了一部分，或做了但只在一种条件下却声称普适 |
| **擦边** | 同一片区域，不同的问题 |
| **反面证据** | 它暗示我们的命题不成立。**这类最要紧，要主动去找** |
| **工具** | 不回答我们的问题，但给了尺子、数据集或基线 |

**派检索代理时必须明确要求它找反面证据。** 一条反面证据比十条支持证据更能改变下一步：如果结论注定无聊，早知道早换。

---

## 5. 检索日志写什么

每条至少包含：

1. **日期 + 这是第几次检索**
2. **起因**：是哪句话、哪个疑问触发的
3. **本地核查**：派代理之前，agent 自己在 `main.tex` 上能查的先查。全文词频、引用关系、是否出现某个措辞——这些本地就能定，不必花代理
4. **派了几个代理，各问什么**
5. **结论**，以及**新增/改动了哪些台账条目**
6. **返回空的查询词清单**

第 3 条是效率关键：**本地词频常常就能定性**。这次就是靠对四篇 `main.tex` 做词频，直接定出「路线上四篇里三篇零命中，一篇只在相关工作里提过一次」。

---

## 6. 子代理简报的固定要求

派检索代理时，简报里必须写全：

- **要检验的命题**，连同它的原始出处和原话，不要让代理自己去猜；
- **判决取值表**（填了 / 填了一半 / 擦边 / 反面证据 / 工具），要求每篇只能选一个；
- **三盏灯的判据全文**，以及「只看核心贡献」「说明是同一贡献还是拼装」；
- 要求每篇给出**一句最有用的原文引用**及其位置；
- 要求**列出返回空的查询词**；
- **明确要求主动找反面证据**，并说明为什么要找；
- 「无法从一手来源核实的就说无法核实」。

## 7. 这套东西解决的是什么问题

用户的原话是「我拥有锤子，但我并不是有钉子才有的锤子」。读论文本身不产生钉子，产生钉子的是**把每次检索的结果累积到同一个地方，并且用同一把尺子量**。

三盏灯这把尺子的作用，不是给论文打分，是**让「我的问题够不够格」这件事可比较**：手上的候选亮几盏、离它最近的已有工作亮几盏、还空着的是哪一盏。

**最有价值的一次记录，往往是发现「钉子的一块已经被人做掉了」。** 这次就是：用户以为「数据好坏随消费者变」是自己的猜想，本地核查发现阅读路线上的第 4 篇已经在真机上做掉了这一块，于是钉子从三块收缩到两块，阅读顺序也跟着调整。**没有这个文件，这个发现会散在聊天记录里。**

## 8. 三盏灯的校准结果（2026-09-18 实测，别再凭印象说）

派了一个代理专门校准这把尺子本身。结论有三条，**都和直觉相反，要写进文件让用户看到**。

### 8.1 三盏灯不换奖，这是民间传说

逐页抓 CoRL 2021–2025 与 RSS 2021–2025 的官方奖项页（注意：**2023、2024 的会议页只列入围不标获奖**，获奖要去 RSS Foundation 的登记页取）。把 RSS 全部 17 位获奖者按同一判据打灯：

| 灯 | 17 位获奖者里几篇亮 |
|---|---|
| R 机器人（真机） | **15 / 17** |
| M 机器学习（证明或隔离消融） | **3 / 17** |
| A 人工智能（把模糊说法变成能算的新量） | **≈ 0 / 17** |

另一侧：13 篇被检视的主要论文里只有一篇有任何奖（还是入围，还是两灯三拼装），Diffusion Policy 4211 引零奖。**引用追踪的是机器人灯单独一盏。**

**所以要对用户说清**：三盏灯买到的是**一个能在跨系委员会前站住的选题**，不是奖。这是两个目标。

### 8.2 两种暗灯的可修复性完全不同

- **ML 暗的大多修不好**——需要一个自己没有的证明，作者常在局限里直接承认。
- **机器人暗的大多是能修而没修**——理论组把论文发在仿真上，而同一个组天天跑真机。

**推论，也是这次给用户最有用的一句**：**最便宜的三灯选题不是造一把新尺子，而是把一个现成的定理搬到真机上。** 找那种「被整条线当理论许可证引用、却从没上过硬件」的定理。

### 8.3 判「一次性点亮」的实操测试

两个站得住的范本共有、而所有「差一盏」的都缺的性质：**它们算的那个量，是机制的推论，不是事后被解释的测量。**

> **一句话测试**：如果你提出的那个量，**写不成你所主张机制的推论**，那你有的是两个贡献而不是一个，评审时必有一盏灯是暗的。

这条比第 3.1 节那个「删掉一部分看另外两盏灭不灭」更好用，因为它在**提案阶段**就能用。

### 8.4 一个必须告诉用户的事实

**没有任何一篇论文用这个三方框架写作。** 专门搜过，只找到两方的表述（Edward Johns, CoRL 2021 blue-sky，机器人 vs 机器学习）。**A 灯在这片文献里没有任何社群以它自命。**

含义：**三盏灯是一副诊断镜片，不是论文实际被写作或评审的方式。** 用它来选题可以，用它来预测评审反应不行。

## 9. agent 自己容易跑偏的地方（2026-09-18 用户点名）

用户在本轮结束时问「你偏差到哪里去了」。如实记录，供以后自检：

1. **把「核查某篇有没有得奖」扩张成「这个模式能不能得奖」。** 前者是用户要求过的事实核查（硬规矩 13），后者是 agent 自己发明的研究问题，并为此专门派了一个代理。
2. **派出的代理里有一个不在用户的要求范围内**——用户说的是「搜搜看有没有相似的」，那个代理做的却是校准 agent 自己定的准则。
3. **agent 自己给钉子连改了三个版本。** 用户要求的是「维护和记录」，下研究判断是加出来的。
4. **准则长出了用户没要求的整整一节。**

用户对这些 drift 的裁定是「你这样做是对的」，**所以不必回退**；但规矩是：**派代理前，把「这一个代理回答的是用户的哪句话」写进简报开头**；如果写不出来，就在派之前先问一句。**drift 可以有，但要让用户看得见。**

## 10. 本地核查经常比派代理更值钱（2026-09-18 第 5 次检索的实例）

§5 已经写了「派代理前先在 `main.tex` 上查能查的」。这里补一个实例，因为它**改掉的是问题本身，不只是省了一个代理**。

用户提出「CUPID 的影响函数能不能当一个廉价的 eval 替代品」，起因是他自己付过的账：BEHAVIOR-1K 后训练，训练一次 64 GPU-hours，**评测一次约 300 GPU-hours**。

派代理之前，对 CUPID `main.tex` 做词频，三分钟得到：

| 查的 | 命中 | 结论 |
|---|---|---|
| `rollout` | 85 | **它消耗 rollout，不产生 rollout。替代不了 eval。** |
| `offline policy evaluation` | 0 | 从没和这条线接上 |
| `evaluation cost` / `expensive` | 0 / 0 | 从没讨论过评测开销 |

**如果直接派代理去「找一个免 rollout 的影响函数」，那个代理会白跑**，因为前提就不成立。

但同一次核查捞出了它写下的一句机制——「**it suffices to rank** … (requiring fewer rollouts) rather than to **estimate** … precisely (requiring many rollouts)」，配上实测的「排序在 $m\in[25,50]$ 稳定，报成绩用 500」。**可迁移的是这条原理，不是这个工具。** 命题因此从「影响函数能不能免评测」变成「**排序比估计便宜一个量级，能不能做成有保证的评测协议**」——后者有现成理论（best-arm identification 的样本复杂度界），前者没有。

**教训写死**：本地核查不只是「省代理」，它经常**在派代理之前就把问题改对**。规矩是——**用户提出一个新命题时，先在他引用的那篇原文上把命题的前提核一遍，再决定派什么代理。**
